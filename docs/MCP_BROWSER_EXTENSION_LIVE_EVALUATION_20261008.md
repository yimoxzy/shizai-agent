## 发现并修复的问题（源码，尚未发布）

扩展 0.1.9 的重复行推断把首张卡片的子节点位置生成相对 selector，其他卡片只要该位置
存在节点就算通过。插入广告或排名后，样例价格会变成广告文案，仍错误标记 verified。
本次原生字段使用了原始取点选择器，所以原生预览和最终缓存的价格正确；这不能证明扩展
推断样例本身正确。

源码扩展版本提高为 0.1.10，修复内容：

- 从所选节点的属性、类名和来源 selector 构造字段身份，逐行验证唯一命中。
- 不凭兄弟位置跨卡片推断；字段缺失、多重命中、两个字段坍缩到同一节点、
  或选定行外仍有同字段可见命中时拒绝绑定，不悄悄丢行。
- 样例值与 `fieldSelector` 来自同一批验证节点。`sourceSelector` 保留输入证据。
- Python 原生适配器只使用扩展核验的 `fieldSelector`，不再在服务端删除位置条件，
  也不回退到未经验证的位置路径；旧扩展响应缺少逐行身份验证时提示升级、重载后重新取点。
- manifest、content core、worker 与 Python 默认扩展版本同步。安装目录与发布清单未手工修改。

验证：JavaScript 14 passed；Python 浏览器、MCP 绑定与多进程桥接回归 37 passed；
发布源码版本检查 1 passed；Ruff、Node 语法和 diff 空白检查通过。
JavaScript 是 DOM 夹具回归，**修复后的 0.1.10 尚未在实际 Chrome 中加载验收**。
本轮未构建或发布 MCP 0.7.30；当前安装和 npm latest 仍是此前发布的 0.7.29。
