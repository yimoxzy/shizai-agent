# Luna 原生 RPA 创建与持续编辑测评

2026-09-08 至 09 日，在本机实在设计器上用真实 `gpt-5.6-luna`、medium 推理运行。
目标是通过实测优化 MCP；不是让测试模型修改源码，也不是脚本替模型指定工具调用顺序。

## 测试条件

- 使用 Codex 0.153.4 的 app-server 创建独立、持久化普通会话，已在应用中打开。
  核验 model/list 和 thread/start 均解析为 `gpt-5.6-luna`，禁用模型回退。
- 每个会话注入本地源码 MCP，工具集为 `rpa-authoring`；测试进程使用完全访问权限、never 审批、该 MCP 自动授权。
  全局 Codex 配置未修改。会话不读取实现或之前模型的答案，业务操作只能通过 MCP。
- 每轮只新建 `Luna评测` 开头的测试应用；第二句必须修改同一应用。
  输出只在工作区 `_tmp/luna-eval/data`，不使用 shell/Python 代替 RPA 写入业务文件。
- 创建阶段要求保存、严格静态检查、不运行；编辑阶段改两个参数，预览、保存、运行一次并核对内容。
  提示词见 `tests/evals/luna-text-roundtrip.json`。
- 初次会话因为 MCP 宿主授权配置拒绝所有工具，单列为基础设施失败，不计入模型编写失败。
  修复会话权限后才进行下面的原生测试。

创建回合结果字符量减少约 89.7%。这组版本在迭代中改变了多个因素且没有重复抽样，不能视为受控速度或成功率实验。

实际原生节点和文件证据确认：等待变为 2 秒，文本变为“Luna 修改成功”，读取组件仍启用变量打印。
运行返回成功终态，`output_files[].text_evidence` 是完整 UTF-8 文本，`fresh_for_run=true`。

## 暴露的问题与落地修复

1. 目录每次返回大量重复选型指导，即使无结果也约 25,000 字符。compact 保留同一组件契约和分页，去掉重复全局信息。
2. start_design 回执携带完整目录、多份计划和节点状态，V2 的协议记录达到百万字符量级并出现嵌套截断。
   精简创建回执保留项目身份、步骤校验、未绑定信息与恢复动作。
3. V3 主动选择 full，说明仅设置 default 不足。精简工具集固定 compact，不再要求模型做展示模式选择。
4. Basic_DebugOutput 等设计器静态入口曾被目录标为可物化；已与写入边界一致标为不可物化。
5. 明确变量语法 `{"variable":"name"}`；对疑似 `$name` 字面量提示，但不擅自改变合法字符串含义。
6. 文本运行结果新增最多 8 KiB 的预览、编码、截断、脱敏和完整标记，帮助模型直接核对业务结果。
7. 去除预检两次报错后的强制停止；预检不初始化桌面客户端。只读工具标注 MCP annotations。
8. 精简工具集静态检查后的顶层下一步避免提示未挂载的 validate_project。
   V5 暴露了改成调试提示仍会绕路，最终改为“用户要求整体执行时调用 run”，由 run 内部执行项目诊断。
9. CLI 补齐分析和计划预检命令，与 MCP 共用核心；独立 Luna CLI 基线生成的计划已通过新增预检。
10. V4 首次目录查询仍按分析建议拉取 40 个完整契约，单次约 23 万字符。精简集改为建议先读 summary，再按真实 type 读取 contract。
11. V4 的本次运行已成功，但 status 把 9 月 5 日的文本错误日志判作当前错误。共享核心现按提交时间过滤 JSON 和本地桌面时间戳，
    同时排除旧记录的续行和截取日志尾部时的半条记录；保留本次真实错误优先于文件存在的规则。
    修复后重新查询同一个 V4 运行，结果为 succeeded、error=null，不需要重跑或修改业务文件。
12. V5 把 analysis 缩成 ID，并重写 query，连续遭遇创建拒绝，最终自行修正后仅创建一个应用。
    后续补齐 start_design 的缓存恢复：可以只回传 analysis_id；原句确实变化时仍拒绝，
    但返回准确的 original_query、analysis_reference 和重试工具，避免让模型继续猜原句。
    这一恢复提示补丁由单独回归验证，V5 的模型会话没有热加载该补丁，V6 已加载。
13. V5 因文件任务的元素预检无适用节点，转入 DAP 后单步和状态调用超时。调试停止返回 stopped、cleanup_complete=true；
    会话因 600 秒预算中断，独立复核确认正式运行 never_started、文件未生成。
    精简集现将调试限定为按需定位问题，完整图的授权执行使用 run/status；这避免正常路径依赖该问题，不代表底层 DAP 超时已修复。

## 复现

先启动并登录本机实在设计器，在工作区安装源码依赖，然后执行：

```powershell
.\.venv\Scripts\python.exe scripts/luna_rpa_eval.py `
  --codex '你的 Codex 0.153.4 或兼容版本 codex.exe 绝对路径' `
  --prompts tests/evals/luna-text-roundtrip.json `
  --case-name 'Luna评测-文本往返-新编号' `
  --output _tmp/luna-eval/新编号 --timeout 600
```

为每次测试使用新编号，避免复用上次已修改应用。日志包含 `events.jsonl`、`report.json`、
`app-server.stderr.log`。报告记录解析后的模型、会话 ID、每轮工具调用、耗时、结果字符数。
`completed` 只代表模型回合结束，不能用作业务成功判据；仍须检查实际 `.task`、运行终态和文件内容。

本机历史证据保存在 `_tmp/luna-eval/mcp-authoring-v2` 至 `mcp-authoring-v6`。
独立文件复核在 `_tmp/luna-eval/independent-verification.json`，检查实际节点 ID/顺序、目标节点的参数差异、
同一应用编辑、运行次数和真实 UTF-8 文件内容；创建调用被拒绝不计作实际新建应用。
原始日志留在本机；不把桌面状态和个人路径复制进发布包。

## 结论适用范围

后续的文件转换、Excel、CSV、原生控制流、网页查询/分页与结构编辑实测，见
[LUNA_RPA_EXPANDED_EVALUATION.md](LUNA_RPA_EXPANDED_EVALUATION.md)。下文保留本轮单场景的历史边界。

这是单个文本往返任务上的迭代实测，模型每轮自主选型，所以节点数量也可能变化。
字符数包含协议封装，不等于 tokenizer 统计；耗时受模型服务和桌面运行器影响，不能直接推导普遍加速比。
这轮修复了已复现的旧时间戳与半行日志污染；尚不能将没有时间戳或唯一运行标识的日志当作严格隔离的运行账本。
文本验收依赖本次运行信号和新鲜文件内容，不能只搜索“成功”日志。

已验证的范围是简单原生文件流程创建与现有节点参数修改。网页 selector、登录挑战、循环分支、
节点插入删除及跨进程恢复尚未经过这轮 Luna 测评。当前编辑 revision 是乐观冲突检测，仍非多文件事务或设计器锁。
本轮没有运行 Qwen 权重，不能以 Luna 结果承诺 Qwen 27B 成功率。后续应在同一用例集上接入具体模型、重复运行并补齐复杂任务。
